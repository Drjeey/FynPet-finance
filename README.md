# FynPet — Financial Intelligence

A personal finance app for Kenya: transactions, budgets, analytics, M-Pesa statement import and an AI advisor powered by Claude.

- **Front end:** one static page, `public/index.html` (vanilla HTML/CSS/JS with browser ES modules; no bundler).
- **Server:** Netlify Functions in `netlify/functions/`. They hold the secrets and call Anthropic.
- **Data:** the browser's `localStorage`, synced to Supabase (Postgres + Auth + row-level security) when you sign in.

The development roadmap is in [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).

## Project structure

```
public/                       The only published folder
  index.html                  Markup and styles
  app.js                      Front-end state and UI (no inline scripts or handlers — CSP)
  calc.js                     Pure currency, period, chart and financial calculations
  vendor/                     Generated by `npm run build` (PDF.js, supabase-js); not committed
scripts/
  build.mjs                   Copies pinned browser libraries into public/vendor/
supabase/
  migrations/001_init.sql     Database schema with row-level security
netlify/
  functions/
    ai.mjs                    POST /api/ai     — AI advisor + M-Pesa extraction (auth, quotas, prompts)
    config.mjs                GET  /api/config — Supabase URL + anon key, AI availability
  lib/
    auth.mjs                  Supabase token check, per-user daily quota (Netlify Blobs)
    http.mjs                  Response helpers
tests/
  calc.test.mjs               Currency, date boundaries, charts and emergency coverage
  ai.test.mjs                 Function tests against local mocks (no real API calls)
  schema.test.mjs             Runs the migration on in-process Postgres and checks RLS
netlify.toml                  Build, functions, security headers and Content-Security-Policy
.env.example                  Environment variables template
```

## How a request flows

```
Browser ──GET  /api/config──▶ config.mjs ──▶ returns SUPABASE_URL, SUPABASE_ANON_KEY
Browser ──sign in──────────▶ Supabase Auth ──▶ access token
Browser ──POST /api/ai (Bearer token)──▶ ai.mjs
            1. verifies the token with Supabase Auth           (401 if missing/invalid)
            2. per-IP rate limit: 20 requests/min               (429)
            3. per-user daily quota: AI_DAILY_LIMIT             (429)
            4. builds the prompt server-side, redacts phone numbers
            5. calls Anthropic with ANTHROPIC_API_KEY ──▶ validated JSON back to the browser
```

AI features need a signed-in user. Everything else works offline, in local-only mode.

## Environment variables

Set these in **Netlify → Site configuration → Environment variables**. For local development, copy `.env.example` to `.env`.

| Variable | Required | Scope | Notes |
|---|---|---|---|
| `ANTHROPIC_API_KEY` | Yes | Functions | Mark as **secret**. Never put it in the HTML. |
| `SUPABASE_URL` | Yes | Functions | `https://<project-ref>.supabase.co` |
| `SUPABASE_ANON_KEY` | Yes | Functions | The public **anon** key, never the `service_role` key |
| `ANTHROPIC_MODEL` | No | Functions | Default `claude-opus-5-5` |
| `AI_DAILY_LIMIT` | No | Functions | AI requests per user per day. Default `60` |

To set them with the Netlify CLI instead (after `netlify link`):

```bash
netlify env:set ANTHROPIC_API_KEY "sk-ant-..." --secret --context production deploy-preview --scope functions
netlify env:set SUPABASE_URL "https://xxxx.supabase.co" --scope functions
netlify env:set SUPABASE_ANON_KEY "eyJ..." --scope functions
```

After changing a variable, redeploy so the functions pick it up.

## Local development

Requires Node.js 22+.

```bash
npm install
cp .env.example .env        # then fill in the values
npm run dev                 # builds public/vendor/, then serves the site + functions on http://localhost:8888
```

```bash
npm test                    # function + database tests, fully offline (no API calls)
```

**Front-end rules (enforced by the Content-Security-Policy):** no inline `<script>`, no `onclick=""` attributes, no CDN scripts. Wire events with `data-click="action"` plus `data-click-args='[...]'` (the same for `input`, `change` and so on), and add the function to `ACTIONS` in `app.js`. Escape every value that comes from data with `escHtml()` before putting it in HTML.

## Deploying

Deploy from Git. Drag-and-drop no longer works because the functions have npm dependencies.

1. Push the repository to GitHub (or GitLab or Bitbucket).
2. In Netlify, choose **Add new project → Import an existing project**, then pick the repository. `netlify.toml` already sets publish = `public` and functions = `netlify/functions`.
3. Add the environment variables above and deploy.
4. Check that `https://<your-site>/api/config` returns `"aiEnabled": true`.

Alternatively, deploy from your machine: `npx netlify-cli deploy --build --prod`.

## Supabase setup

1. Create a project on [supabase.com](https://supabase.com). A region near Kenya, such as `eu-west`, keeps latency down.
2. In the **SQL Editor**, run `supabase/migrations/001_init.sql` once, on a new, empty project.
3. Under **Advisors → Security Advisor**, confirm there are no errors.
4. Under **Authentication → URL configuration**, set the Site URL to your Netlify URL.
5. Copy the **Project URL** and **anon public** key into the Netlify environment variables.

## Currency calculations

Totals, budgets, charts, exports and advisor context use each transaction's saved KES conversion. Settings contains editable estimates for USD, EUR, GBP, TZS and UGX; these are not live rates. New or edited transactions use the current setting, while existing saved conversions stay unchanged. Legacy local records without a conversion are converted once on load. The database field is `amount_kes`; the local field is `amountKes`.

Calendar calculations use Africa/Nairobi even when the device uses another timezone. Emergency coverage is savings divided by average expenses over the last three completed calendar months, including months without expenses. No expense history returns zero coverage.

## M-Pesa import

1. Upload the PDF and enter the password: your National ID number, Safaricom's default.
2. PDF.js decrypts the file and extracts the text **in your browser**. The PDF itself is never uploaded.
3. The text is sent in small chunks to `/api/ai`. The server strips phone numbers and asks Claude for structured JSON.
4. Rows are validated on the server. Transactions already imported (same M-Pesa receipt number) are skipped.

Note that the transaction text, which includes merchant and counterparty names, is processed by Anthropic.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Settings shows "AI ✕ Not configured" | `ANTHROPIC_API_KEY` or `SUPABASE_URL` is missing in Netlify. Set it and redeploy. |
| "Sign in to use AI features" | AI requires a Supabase account. Use the sign-in dialog. |
| "Daily AI limit reached" | Raise `AI_DAILY_LIMIT`, or wait for the midnight UTC reset. |
| "The AI took too long to respond" | Netlify functions stop at 60 s. Retry, or import a shorter statement period. |
| `/api/config` returns 404 locally | Use `npx netlify-cli dev`, not a plain static server. |
